## PROBLEMS:

- **test_req2_item_validation**: `assert svc.add_item("", "Hammer", "Tools", 5, 7)[0] == 400` — the specification only returns 400 for `total_qty` ≤ 0 or `duration_days` ≤ 0 (L26); it never says an empty `item_id` is invalid.
- **test_req3_unpaid_fines_block_borrow**: `svc.members["debtor"]["fines"] = 10.0` — the specification defines no internal state layout, so a spec-conforming implementation need not expose `svc.members[username]["fines"]`.
- **test_req5_return_and_fines**: `assert svc.return_item(loan_id, "good") == (200, {"fine": 0.0, "status": "good"})` — the specification (L13) declares a `status` field but never fixes its content, so requiring the exact value `"good"` is the author's decision.
- **test_req5_fractional_overdue_ceiling**: `assert res[1]["fine"] == 2.0` on a 1-second overdue return — the author's notes explicitly declare partial-seconds overdue handling "deliberately left open", so this must not be tested.
- **test_req9_damaged_and_lost**: `assert svc.items["i1"]["available"] == 1` and `assert svc.items["i2"]["total_qty"] == 0` — these inspect an internal `svc.items` dictionary whose structure the specification never describes; the effects themselves (L32, L40) are only required to be observable through the API.
